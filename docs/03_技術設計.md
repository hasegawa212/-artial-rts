# STEP 3 技術設計

| 層 | 採用 |
|---|---|
| フレームワーク | Next.js 16（App Router, `proxy.ts`）+ React 19 + TypeScript 5.9 strict |
| UI | Tailwind CSS 4 + shadcn/ui 方式の部品（cva + tailwind-merge を `src/components/ui/` に直置き。CLI はネット接続が必要なため手書き） |
| DB | PostgreSQL 16 + Prisma 7（`@prisma/adapter-pg`） |
| 認証 | OIDC（openid-client v6、Authorization Code + PKCE + state + nonce） |
| 権限 | RBAC（member / manager / admin）|
| テスト | Vitest（単体・契約）、Vitest + PostgreSQL（結合）、Playwright（E2E） |
| CI | GitHub Actions（`.github/workflows/martial-arts-one.yml`） |

## 層の分け方
- `src/domain/` … 純粋関数（RBAC・検索・起動判定・台帳）。サーバー/ブラウザ両方で使う。
- `src/server/` … 設定（zod で検証）・セッション・OIDC の claims 解決・リポジトリ（`PortalRepo` インターフェース、メモリ実装と Prisma 実装は同じ契約テストを通る）。
- `src/app/` … 画面・Route Handler・Server Actions。

## 認証
1. `/api/auth/login` → IdP（Google Workspace / Entra ID / Okta など OIDC 対応なら可）へ。PKCE verifier・state・nonce は暗号化 Cookie（10 分）。
2. `/api/auth/callback` → トークン交換・ID トークン検証 → `email_verified` 必須、`ALLOWED_EMAIL_DOMAINS` で社外を拒否 → ロール決定 → 監査ログ。
3. セッションは **JWE（A256GCM）暗号化 Cookie**（httpOnly・SameSite=Lax・本番 Secure・8 時間）。
4. ロールは毎リクエスト DB の値を使う（降格は即時反映）。`ADMIN_EMAILS` / `MANAGER_EMAILS` に書かれた人はログイン時にそのロール以上。自分自身の管理者権限は外せない。

## RBAC
| 権限 | member | manager | admin |
|---|---|---|---|
| アプリを見る・開く | ✓ | ✓ | ✓ |
| 管理者画面を見る・監査ログ | | ✓ | ✓ |
| アプリ台帳の編集・ロール変更 | | | ✓ |

アプリごとに「閲覧できる最低ロール」を持ち、社外秘は member に出さない（テストで強制）。権限のないアプリは詳細も 404。

## 安全のための決まり（ブリーフの遵守事項との対応）
- **既存アプリに触らない**：ポータルはリンクで開くだけ。起動は `POST /api/apps/[id]/launch` → 権限・URL を確認 → 履歴・監査ログ → 303 で移動。既存アプリの認証・API・DB には接続しない（#1 #4 #5）。
- **推測で接続しない**：URL 状態が「URL未確認」なら URL があっても開かない。https 以外・認証情報入り URL（user:pass@、token= など）も開かない（#8）。
- **外部送信なし**：電話・メール・顧客データ更新のコードは無い（#6）。
- **fail-closed な設定**：既定は OIDC。`AUTH_MODE=dev` は本番で起動拒否、本番は DB・https・32 文字以上の秘密鍵が必須。
- CSRF：状態を変える POST は Origin を検査、Server Actions も Next.js が検査。
- ヘッダー：CSP（外部読み込みなし）・X-Frame-Options DENY・nosniff・Referrer-Policy。
